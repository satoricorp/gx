title: "GitHub PR summaries from GX Cloud"
description: "Learn how GX Cloud posts a single rich PR summary comment after you publish with git push and open a pull request."
---

When a branch is published through GX (`git push` with the pre-push hook) and a
GitHub pull request exists, GX Cloud posts a single rich summary comment on the
PR. The summary helps reviewers see what changed, how risky it is, and where to
focus — without you authoring a description by hand.

## When this runs

GX Cloud posts the summary automatically when:

- You `git push` a GX branch (pre-push hook uploads the review artifact), and
- A pull request exists for that branch (`gh pr create` or the GitHub UI), or
- The GitHub App sees `pull_request` opened/synchronized for a branch that already has GX context.

No CLI PR-body rewrite is involved. There is one summary path: the GitHub issue
comment owned by GX Cloud.

## What the comment contains

The generated comment matches the rich review format:

- **Opening triage** — a short verdict banner plus a one-paragraph overview
- **Blast Radius** — LOW / MEDIUM / HIGH with file/area/line counts and a risk note
- **Notable Changes** — high-impact review targets, each with an Attribution line
- **Footer** — `*Generated by GX.*`

## Working with the summary

- Create or update the PR after publishing with `git push`.
- Do not run `gx push` — it is disabled; plain `git push` is the publish path.
- Force a refresh by pushing again (or reopening the PR flow) so Cloud regenerates from the latest artifact.
