title: "GX: stacked PR review for agentic coding sessions"
description: "Capture agent coding sessions as reviewable revisions, organize them into local stacks, and push stacked pull requests with rich review context."

GX captures coding sessions and attaches that context to reviewable revisions, then uses those revisions to push stacked PRs and generate better review artifacts.

## Download

```bash
curl -fsSL https://download.gx.run/install.sh | sh
```

To uninstall the CLI and menu-bar app:

```bash
rm -f ~/.local/bin/gx ~/.local/bin/gxr ~/.local/bin/gxs ~/.local/bin/gx-mcp
rm -rf /Applications/GX.app ~/Applications/GX.app
```

This removes the installed binaries and app bundle only. Local GX data remains
in `~/.gx`.

## Core Workflow

```bash
git add <files>
gx commit -m "describe this revision"
gx status
git push
gh pr create
```

`gx commit` records staged work as a GX revision. Plain `git push` publishes the
branch; the GX pre-push hook captures the session and uploads review context.
Open the PR with `gh pr create` — GX Cloud posts the rich PR summary comment.
Do not run `gx push`.

For a manual Git-like save path, stage exactly what you want and replace
`git commit` with `gx commit`:

```bash
git add <files>
gx commit -m "describe this revision"
git push
```

`gx commit` records the staged tree as a Git-native GX revision. To update the
latest revision, use `git commit --amend` and preserve the GX revision trailer.

## Local Inference

For open-source inference, run:

```bash
gx set key
```

Choose Anthropic or OpenAI, then paste the API key. GX stores one key in `~/.gx/inference.json` or `$GX_HOME/inference.json` and injects it for local inference proxying and MCP-launched gx commands. `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` remain supported as fallbacks; the stored key wins when present.

## Agent Setup

<Note>
  Add GX instructions to the start or end of your `AGENTS.md` or `CLAUDE.md`
  so agents save with GX instead of raw Git. Prefer the GX MCP tools first, and
  use the CLI as the fallback.
</Note>

```md
Version control: use Git with GX hooks and metadata, not raw `git commit` for normal agent work.

Use GX MCP first:
- `gx_commit` after `git add` to record staged work (default verb).
- `gx_status` to inspect local and remote stack state.

To amend an existing GX revision, use `git commit --amend` and preserve the GX revision trailer.

Publish with plain `git push` (the GX pre-push hook captures the session and publishes),
then open the PR with `gh pr create`. Do not run `gx push` or `gx capture push`.

If MCP is unavailable, use the CLI fallback:
- `git add <files>` then `gx commit -m "..."` for manual saves
- `gx status`
- `git push`

When the user says "save work", "save using gx", or "save with gx", run the
GX save workflow: stage with `git add`, record with `gx_commit`, inspect with
`gx_status`, and publish ready stacks with plain `git push` unless the user asks to keep them local.

GX PR summaries are posted by GX Cloud for PRs whose branch was pushed through GX
with `git push` while the pre-push hook is installed.

Use raw Git for read-only inspection and the `git push` publish step; do not use other raw
Git for the save flow unless the user explicitly asks. If your agent client supports tool
policies, deny or require approval for `git commit`, `git reset`, and branch deletion.
```

<Info>
  Installing the GX menu-bar app installs the bundled `gx` CLI and `gx-mcp`.
  When a repo is initialized with `gx init` or by MCP auto-initialization, GX
  installs Git lifecycle hooks: `prepare-commit-msg` stamps the GX trailer,
  `post-commit` records commit metadata, `post-rewrite` follows amended or
  rebased commit OIDs, and `pre-push` captures Claude/Codex/Cursor session
  context into `~/.gx/gx.db` and publishes when credentials are configured.
</Info>

## Product Model

GX centers the reviewable revision rather than the branch:

- **Session**: captured context from agent prompts, responses, commands, tests, and files touched.
- **Revision**: one logical change with attached evidence.
- **Stack**: an ordered set of revisions that can be published as stacked PRs.

JJ provides the local change engine, and Git remains the remote compatibility layer.
