				var excludesKey = "";
				var blocked = {};

					if (Object.prototype.hasOwnProperty.call(blocked, c)) continue;

				}
			} catch (e) {}
		})();;

					<div class="content"><p>.NET compiler platform (Roslyn) analyzers inspect your C# or Visual Basic code for code quality and style issues. These analyzers are included with the .NET SDK and you don't need to install them separately. If your project targets .NET 5 or later, code analysis is enabled by default. (For information about enabling code analysis in projects that target .NET Framework, see <a href="#enable-code-analysis-in-legacy-projects" data-linktype="self-bookmark">Enable code analysis in legacy projects</a>.)</p>
<p>If rule violations are found by an analyzer, they're reported as a suggestion, warning, or error, depending on how each rule is <a href="configuration-options" data-linktype="relative-path">configured</a>. Code analysis violations appear with the prefix "CA" or "IDE" to differentiate them from compiler errors.</p>
<h2 id="code-quality-analysis">Code quality analysis</h2>
<p><em>Code quality analysis</em> ("CAxxxx") rules inspect your C# or Visual Basic code for security, performance, design and other issues. Analysis is enabled, by default, for projects that target .NET 5 or later. You can enable code analysis on projects that target earlier .NET versions by setting the <a href="../../core/project-sdk/msbuild-props#enablenetanalyzers" data-linktype="relative-path">EnableNETAnalyzers</a> property to <code>true</code>. You can also disable code analysis for your project by setting <code>EnableNETAnalyzers</code> to <code>false</code>.</p>
<div class="TIP">
<p>Tip</p>
<p>If you're using Visual Studio, many analyzer rules have associated <em>code fixes</em> that you can apply to automatically correct the problem. Code fixes are shown in the light bulb icon menu.</p>
</div>

<li>For a list of rules that are included with each .NET SDK version, see <a href="https://github.com/dotnet/sdk/blob/main/src/Microsoft.CodeAnalysis.NetAnalyzers/src/Microsoft.CodeAnalysis.NetAnalyzers/AnalyzerReleases.Shipped.md" data-linktype="external">Analyzer releases</a>.</li>

<h3 id="enable-additional-rules">Enable additional rules</h3>
<p><em>Analysis mode</em> refers to a predefined code analysis configuration where none, some, or all rules are enabled. In the default analysis mode (<code>Default</code>), only a small number of rules are <a href="#enabled-rules" data-linktype="self-bookmark">enabled as build warnings</a>. You can change the analysis mode for your project by setting the <a href="../../core/project-sdk/msbuild-props#analysismode" data-linktype="relative-path"><code>&lt;AnalysisMode&gt;</code></a> property in the project file. The allowable values are:</p>
<table>
<thead>
<tr>
<th>Value</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>None</code></td>
<td>All rules are disabled. You can selectively <a href="configuration-options" data-linktype="relative-path">opt in to</a> individual rules to enable them.</td>
</tr>
<tr>
<td><code>Default</code></td>
<td>Default mode, where certain rules are enabled as build warnings, certain rules are enabled as Visual Studio IDE suggestions, and the remainder are disabled.</td>
</tr>
<tr>
<td><code>Minimum</code></td>
<td>More aggressive mode than <code>Default</code> mode. Certain suggestions that are highly recommended for build enforcement are enabled as build warnings. To see which rules this includes, inspect the <em>%ProgramFiles%/dotnet/sdk/[version]/Sdks/Microsoft.NET.Sdk/analyzers/build/config/analysislevel_[level]_minimum.globalconfig</em> file. (For .NET 7 and earlier versions, the file extension is <em>.editorconfig</em>.)</td>
</tr>
<tr>
<td><code>Recommended</code></td>
<td>More aggressive mode than <code>Minimum</code> mode, where more rules are enabled as build warnings. To see which rules this includes, inspect the <em>%ProgramFiles%/dotnet/sdk/[version]/Sdks/Microsoft.NET.Sdk/analyzers/build/config/analysislevel_[level]_recommended.globalconfig</em> file. (For .NET 7 and earlier versions, the file extension is <em>.editorconfig</em>.)</td>
</tr>
<tr>
<td><code>All</code></td>
<td>All rules are enabled as build warnings<sup>*</sup>. You can selectively <a href="configuration-options" data-linktype="relative-path">opt out</a> of individual rules to disable them.<br><br>* The following rules are <em>not</em> enabled by setting <code>AnalysisMode</code> to <code>All</code> or by setting <code>AnalysisLevel</code> to <code>latest-all</code>: CA1017, CA1045, CA1005, CA1014, CA1060, CA1021, and the code metrics analyzer rules (CA1501, CA1502, CA1505, CA1506, and CA1509). These legacy rules might be deprecated in a future version. However, you can still enable them individually using a <code>dotnet_diagnostic.CAxxxx.severity = &lt;severity&gt;</code> entry.</td>
</tr>
</tbody>
</table>
<p>You can also omit <a href="../../core/project-sdk/msbuild-props#analysismode" data-linktype="relative-path"><code>&lt;AnalysisMode&gt;</code></a> in favor of a compound value for the <code>&lt;AnalysisLevel&gt;</code> property. For example, the following value enables the recommended set of rules for the latest release: <code>&lt;AnalysisLevel&gt;latest-Recommended&lt;/AnalysisLevel&gt;</code>. For more information, see <a href="../../core/project-sdk/msbuild-props#analysislevel" data-linktype="relative-path"><code>AnalysisLevel</code></a>.</p>
<p>To find the default severity for each available rule and whether or not the rule is enabled in <code>Default</code> analysis mode, see the <a href="https://github.com/dotnet/roslyn-analyzers/blob/main/src/NetAnalyzers/Core/AnalyzerReleases.Shipped.md" data-linktype="external">full list of rules</a>.</p>
<h3 id="treat-warnings-as-errors">Treat warnings as errors</h3>
<p>If you use the <code>-warnaserror</code> flag when you build your projects, all code analysis warnings are also treated as errors. If you do not want code quality warnings (CAxxxx) to be treated as errors in presence of <code>-warnaserror</code>, you can set the <code>CodeAnalysisTreatWarningsAsErrors</code> MSBuild property to <code>false</code> in your project file.</p>
<pre><code class="lang-xml">&lt;PropertyGroup&gt;
  &lt;CodeAnalysisTreatWarningsAsErrors&gt;false&lt;/CodeAnalysisTreatWarningsAsErrors&gt;
&lt;/PropertyGroup&gt;
</code></pre>
<p>You'll still see any code analysis warnings, but they won't break your build.</p>
<h3 id="latest-updates">Latest updates</h3>
<p>By default, you'll get the latest code analysis rules and default rule severities as you upgrade to newer versions of the .NET SDK. If you don't want this behavior, for example, if you want to ensure that no new rules are enabled or disabled, you can override it in one of the following ways:</p>
<ul>
<li><p>Set the <code>AnalysisLevel</code> MSBuild property to a specific value to lock the warnings to that set. When you upgrade to a newer SDK, you'll still get bug fixes for those warnings, but no new warnings will be enabled and no existing warnings will be disabled. For example, to lock the set of rules to those that ship with version 8.0 of the .NET SDK, add the following entry to your project file.</p>
<pre><code class="lang-xml">&lt;PropertyGroup&gt;
  &lt;AnalysisLevel&gt;8.0&lt;/AnalysisLevel&gt;
&lt;/PropertyGroup&gt;
</code></pre>
<div class="TIP">
<p>Tip</p>
<p>The default value for the <code>AnalysisLevel</code> property is <code>latest</code>, which means you always get the latest code analysis rules as you move to newer versions of the .NET SDK.</p>
</div>
<p>For more information, and to see a list of possible values, see <a href="../../core/project-sdk/msbuild-props#analysislevel" data-linktype="relative-path">AnalysisLevel</a>.</p>
</li>
<li><p>Install the <a href="https://github.com/dotnet/roslyn-analyzers#microsoftcodeanalysisnetanalyzers" data-linktype="external">Microsoft.CodeAnalysis.NetAnalyzers NuGet package</a> to decouple rule updates from .NET SDK updates. For projects that target .NET 5+, installing the package turns off the built-in SDK analyzers. You'll get a build warning if the SDK contains a newer analyzer assembly version than that of the NuGet package. To disable the warning, set the <code>_SkipUpgradeNetAnalyzersNuGetWarning</code> property to <code>true</code>.</p>
<div class="NOTE">
<p>Note</p>
<p>If you install the Microsoft.CodeAnalysis.NetAnalyzers NuGet package, you should not add the <a href="../../core/project-sdk/msbuild-props#enablenetanalyzers" data-linktype="relative-path">EnableNETAnalyzers</a> property to either your project file or a <em>Directory.Build.props</em> file. When the NuGet package is installed and the <code>EnableNETAnalyzers</code> property is set to <code>true</code>, a build warning is generated.</p>
</div>
</li>
</ul>
<h2 id="code-style-analysis">Code-style analysis</h2>
<p><em>Code-style analysis</em> ("IDExxxx") rules enable you to define and maintain consistent code style in your codebase. The default enablement settings are:</p>
<ul>
<li><p>Command-line build: Code-style analysis is <em>disabled</em>, by default, for all .NET projects on command-line builds.</p>
<p>You can <a href="#enable-on-build" data-linktype="self-bookmark">enable code-style analysis on build</a>, both at the command line and inside Visual Studio. Code style violations appear as warnings or errors with an "IDE" prefix. This enables you to enforce consistent code styles at build time.</p>
</li>
<li><p>Visual Studio: Code-style analysis is <em>enabled</em>, by default, for all .NET projects inside Visual Studio as <a href="/en-us/visualstudio/ide/code-generation-in-visual-studio" data-linktype="absolute-path">code refactoring quick actions</a>.</p>
</li>
</ul>
<p>For a full list of code-style analysis rules, see <a href="style-rules/" data-linktype="relative-path">Code style rules</a>.</p>
<h3 id="enable-on-build">Enable on build</h3>
<p>You can enable code-style analysis when building from the command-line and in Visual Studio. (However, for performance reasons, <a href="https://github.com/dotnet/roslyn/blob/9f87b444da9c48a4d492b19f8337339056bf2b95/src/Analyzers/Core/Analyzers/EnforceOnBuildValues.cs#L95" data-linktype="external">a handful of code-style rules</a> will still apply only in the Visual Studio IDE.)</p>
<p>Follow these steps to enable code-style analysis on build:</p>
<ol>
<li><p>Set the MSBuild property <a href="../../core/project-sdk/msbuild-props#enforcecodestyleinbuild" data-linktype="relative-path">EnforceCodeStyleInBuild</a> to <code>true</code>.</p>
</li>
<li><p>In an <em>.editorconfig</em> file, <a href="configuration-options" data-linktype="relative-path">configure</a> each "IDE" code style rule that you wish to run on build as a warning or an error. For example:</p>
<pre><code class="lang-ini">[*.{cs,vb}]
# IDE0040: Accessibility modifiers required (escalated to a build warning)
dotnet_diagnostic.IDE0040.severity = warning
</code></pre>
<div class="TIP">
<p>Tip</p>
<p>Starting in .NET 9, you can also use the <a href="style-rules/language-rules#option-format" data-linktype="relative-path">option format</a> to specify a severity and have it be respected at build time. For example:</p>
<pre><code class="lang-ini">[*.{cs,vb}]
# IDE0040: Accessibility modifiers required (escalated to a build warning)
dotnet_style_require_accessibility_modifiers = always:warning
</code></pre>
</div>
<p>Alternatively, you can configure an entire category to be a warning or error, by default, and then selectively turn off rules in that category that you don't want to run on build. For example:</p>
<pre><code class="lang-ini">[*.{cs,vb}]

# Default severity for analyzer diagnostics with category 'Style' (escalated to build warnings)
dotnet_analyzer_diagnostic.category-Style.severity = warning

# IDE0040: Accessibility modifiers required (disabled on build)
dotnet_diagnostic.IDE0040.severity = silent
</code></pre>
</li>
</ol>
<h2 id="suppress-a-warning">Suppress a warning</h2>
<p>One way to suppress a rule violation is to set the severity option for that rule ID to <code>none</code> in an EditorConfig file. For example:</p>
<pre><code class="lang-ini">dotnet_diagnostic.CA1822.severity = none
</code></pre>
<p>For more information and other ways to suppress warnings, see <a href="suppress-warnings" data-linktype="relative-path">How to suppress code analysis warnings</a>.</p>
<h2 id="enable-code-analysis-in-legacy-projects">Enable code analysis in legacy projects</h2>
<p>If your project targets .NET 5 or later, code analysis is enabled by default. If your project targets .NET Standard or .NET Framework, you must manually enable code analysis by setting the <a href="../../core/project-sdk/msbuild-props#enablenetanalyzers" data-linktype="relative-path">EnableNETAnalyzers</a> property to <code>true</code>.</p>
<p>If your project uses the legacy project file format, that is, it doesn't reference a <a href="../../core/project-sdk/overview" data-linktype="relative-path">project SDK</a>, there are some additional steps you must take to enable code analysis:</p>
<ol>
<li>Add a reference to the <a href="https://www.nuget.org/packages/Microsoft.CodeAnalysis.NetAnalyzers" data-linktype="external">📦 Microsoft.CodeAnalysis.NetAnalyzers NuGet package</a>.</li>
<li>Instead of setting <a href="../../core/project-sdk/msbuild-props#analysislevel" data-linktype="relative-path"><code>AnalysisLevel</code></a>, which isn't understood by non-SDK-style projects, add the following properties to your project file:</li>
</ol>
<pre><code class="lang-xml">  &lt;EffectiveAnalysisLevel&gt;9&lt;/EffectiveAnalysisLevel&gt;
  &lt;AnalysisMode&gt;Recommended&lt;/AnalysisMode&gt;
</code></pre>
<h2 id="third-party-analyzers">Third-party analyzers</h2>
<p>In addition to the official .NET analyzers, you can also install third party analyzers, such as <a href="https://www.nuget.org/packages/StyleCop.Analyzers/" data-linktype="external">StyleCop</a>, <a href="https://www.nuget.org/packages/Roslynator.Analyzers/" data-linktype="external">Roslynator</a>, <a href="https://www.nuget.org/packages/Meziantou.Analyzer/" data-linktype="external">Meziantou.Analyzer</a>, <a href="https://www.nuget.org/packages/xunit.analyzers/" data-linktype="external">XUnit Analyzers</a>, and <a href="https://www.nuget.org/packages/SonarAnalyzer.CSharp/" data-linktype="external">Sonar Analyzer</a>.</p>
