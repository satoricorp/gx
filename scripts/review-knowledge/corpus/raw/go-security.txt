    <h1>Security Best Practices for Go Developers</h1>
    <div class='markdown'>
<p><a href="/security">Back to Go Security</a></p>
<p>This page provides Go developers with best practices for prioritizing the
security of their projects. From automating testing with fuzzing to easily
checking for race conditions, these tips can help make your codebase more
secure and reliable.</p>
<h2 id="scan-source-code-and-binaries-for-vulnerabilities">Scan source code and binaries for vulnerabilities</h2>
<p>Regularly scanning your code and binaries for vulnerabilities helps identify
potential security risks early.
You can use <a href="https://pkg.go.dev/golang.org/x/vuln/cmd/govulncheck" rel="noreferrer" target="_blank">govulncheck</a>,
backed by the <a href="https://pkg.go.dev" rel="noreferrer" target="_blank">Go vulnerability database</a>,
to scan your code for vulnerabilities and analyze which ones actually affect you.
Get started with <a href="/doc/tutorial/govulncheck">the govulncheck tutorial</a>.</p>
<p>Govulncheck can also be integrated into CI/CD flows.
The Go team provides a
<a href="https://github.com/marketplace/actions/golang-govulncheck-action" rel="noreferrer" target="_blank">GitHub Action for govulncheck</a>
on the GitHub Marketplace.
Govulncheck also supports a <code>-json</code> flag to help developers integrate vulnerability
scanning with other CI/CD systems.</p>
<p>You can also scan for vulnerabilities directly in your code editor by using
the <a href="/security/vuln/editor">Go extension for Visual Studio Code</a>.
Get started with <a href="/doc/tutorial/govulncheck-ide">this tutorial</a>.</p>
<h2 id="keep-your-go-version-and-dependencies-up-to-date">Keep your Go version and dependencies up to date</h2>
<p>Keeping your <a href="/doc/install">Go version up-to-date</a> offers
access to the latest language features,
performance improvements and patches for known security vulnerabilities.
An updated Go version also ensures compatibility with newer versions of dependencies,
helping to avoid potential integration issues.
Review the <a href="/doc/devel/release">Go release history</a> to see
what changes have been made to Go between releases.
The Go team issues point releases throughout the release cycle to address security bugs.
Be sure to update to the latest minor Go version to ensure you have the
latest security fixes.</p>
<p>Maintaining up-to-date third-party dependencies is also crucial for software security,
performance, and compliance with the latest standards in the Go ecosystem.
However, updating to the latest versions without thorough review
<a href="https://research.swtch.com/npm-colors" rel="noreferrer" target="_blank">can also be risky</a>,
potentially introducing new bugs, incompatible changes,
or even malicious code.
Therefore, while it&rsquo;s essential to update dependencies for the latest security
patches and improvements,
each update should be carefully reviewed and tested.</p>
<h2 id="test-with-fuzzing-to-uncover-edge-case-exploits">Test with fuzzing to uncover edge-case exploits</h2>
<p><a href="/security/fuzz">Fuzzing</a> is a type of automated testing that
uses coverage guidance to manipulate random inputs and walk through code
to find and report potential vulnerabilities like SQL injections,
buffer overflows, denial or service and cross-site scripting attacks.
Fuzzing can often reach edge cases that programmers miss,
or deem too improbable to test.
Get started with <a href="/doc/tutorial/fuzz">this tutorial</a>.</p>
<h2 id="check-for-race-conditions-with-gos-race-detector">Check for race conditions with Go’s race detector</h2>
<p>Race conditions occur when two or more <a href="/tour/concurrency/1">goroutines</a>
access the same resource concurrently,
and at least one of those accesses is a write.
This can lead to unpredictable, difficult-to-diagnose issues in your software.
Identify potential race conditions in your Go code using the built-in
<a href="/doc/articles/race_detector">race detector</a>,
which can help you ensure the safety and reliability of your concurrent programs.
The race detector finds races that occur at runtime,
however, so it will not find races in code paths that are not executed.</p>
<p>To use the race detector, add the <code>-race</code> flag when running your tests or
building your application,
for example, <code>go test -race</code>.
This will compile your code with the race detector enabled and report any
race conditions it detects at runtime.
When the race detector finds a data race in the program, it will
<a href="/doc/articles/race_detector#report-format">print a report</a>
containing stack traces for conflicting accesses,
and stacks where the involved goroutines were created.</p>
<h2 id="use-vet-to-examine-suspicious-constructs">Use Vet to examine suspicious constructs</h2>
<p>Go’s <a href="https://pkg.go.dev/cmd/vet" rel="noreferrer" target="_blank">vet command</a> is designed to analyze
your source code and flag potential issues that might not necessarily be syntax errors,
but could lead to problems during runtime.
These include suspicious constructs, such as unreachable code,
unused variables, and common mistakes around goroutines.
By catching these issues early in the development process,
go vet helps maintain code quality, reduces debugging time,
and enhances overall software reliability.
To run go vet for a specified project, run:</p>
<pre><code>go vet ./...
</code></pre>
<h2 id="subscribe-to-golang-announce-for-notification-of-security-releases">Subscribe to golang-announce for notification of security releases</h2>
<p>Go releases containing security fixes are pre-announced to the low-volume
mailing list <a href="https://groups.google.com/group/golang-announce" rel="noreferrer" target="_blank">golang-announce@googlegroups.com</a>.
If you want to know when security fixes to Go itself are on the way, subscribe.</p>
