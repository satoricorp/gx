The MCP server ships with the CLI as a local stdio binary. It shells out to the
CLI, so repo state stays on your machine. It exposes one tool: `tx_review`.

## Install

```bash
curl -fsSL https://download.totality.sh/install.sh | sh
tx auth login
```

## Register with your agent

`tx init` registers the server automatically with agent CLIs found on your
`PATH` (Claude Code, Cursor, Codex) and reports something like
`MCP ok: Claude Code, Cursor`.

To register with every MCP client on your machine in one command, use
[`add-mcp`](https://www.npmjs.com/package/add-mcp):

```bash
npx add-mcp @satoricorp/totality --name tx -g -y
```

| Flag | Effect |
| --- | --- |
| `-g` | install user-level so Totality is available in every project; omit for project-level config |
| `-y` | non-interactive (skip prompts) |
| `-a <agent>` | target a specific agent (repeatable), e.g. `-a cursor` |

Most clients load MCP servers at startup — restart the client or open a new
chat after registering.

For clients neither path covers, the stdio shape is:

```json
{
  "mcpServers": {
    "tx": {
      "command": "npx",
      "args": ["-y", "@satoricorp/totality"]
    }
  }
}
```

The server finds the CLI in `~/.local/bin` or on `PATH`; set `TOTALITY_BINARY`
to point somewhere else.

## tx_review

| Parameter | Type | Meaning |
| --- | --- | --- |
| `prompt` | string | optional reviewer prompt, e.g. `"check auth rollback risks"` |
| `scope` | enum | focused lens: `architecture`, `security`, `performance`, `onboarding`, `docs`, `dependencies`, `testing`, `maintainability` |
| `focus` | string | limit review to files under this path prefix |
| `deep` | boolean | full-spectrum review with more local and indexed context |
| `verbose` | boolean | include repo facts, docs, and changed files |
| `repo` | boolean | review the whole repository instead of the current change |
| `cwd` | string | repository working directory (defaults to the MCP server process cwd) |

Runs `tx review` with `--no-publish` always set, so an agent asking for review
context never comments on a pull request. It is read-only and never initializes
a repository. May run up to 5 minutes.

Saving and publishing are plain Git, not MCP calls: `git add` + `git commit`
record the revision through the hooks, `git push` captures and publishes.

## AGENTS.md instructions

`tx init` offers to append these instructions to your repo's `AGENTS.md`. If you
skipped that step, add them manually:

```markdown
Version control: plain Git. Once `tx init` installs the hooks, Totality records
and publishes automatically — there is no Totality save verb.

Default flow:
- Run `git add` to stage the files for this revision.
- Run `git commit -m "..."` to save. A Totality hook records the commit as a reviewable revision.
- Run plain `git push` to publish. The Totality pre-push hook captures the session and
  publishes automatically — do not run `tx push` or `tx capture push` yourself.
- Open PRs with `gh pr create` (or the GitHub UI). Do not seed a `## Summary` in the
  PR body — leave human notes only; Totality Cloud appends the rich summary below.
- To amend, use `git commit --amend` and preserve the Totality revision trailer in the message.

For AI review, run the `tx_review` MCP tool (or the `tx review` CLI) on the current change.
```
